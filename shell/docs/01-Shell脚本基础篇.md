# Shell脚本编写学习总结

近期，我系统学习了Linux Shell脚本编写的相关知识，从最基础的脚本创建与执行，逐步深入到变量操作、算术运算、条件判断、循环控制、文本处理、数组与函数等核心内容，并通过编写多个实用脚本（欢迎脚本、参数处理脚本、计算器、备份脚本、运维工具箱、批量巡检脚本等）将理论知识转化为实践能力。本次总结不仅梳理了各知识点的核心用法、底层原理与常见易错点，还结合了我的实际操作记录和编写的脚本代码，现将学习情况总结如下：

## 一、Shell脚本基础

### （一）脚本创建与执行

**【详细用法】** 

Shell脚本是Linux系统中用于自动化执行命令的文本文件。创建脚本的基本流程为：

1. 使用vim编辑器新建脚本文件（如vim hello.sh）
2. 在首行添加shebang声明解释器（#!/bin/bash）
3. 使用chmod +x 脚本名赋予执行权限
4. 通过./脚本名或bash脚本名两种方式执行

使用bash脚本名执行时不需要执行权限，而./脚本名方式需要chmod +x授权。

**【原理】** 

shebang（#!/bin/bash）是Linux内核的特殊标记，告诉系统该文件应该用哪个解释器来执行。当执行权限被设置后，内核读取文件首行的shebang，找到对应的解释器程序（/bin/bash），并将脚本文件路径作为参数传递给解释器。而使用bash脚本名执行时，是显式调用bash解释器来读取和执行脚本。

**【我的操作记录】** 

在创建第一个Hello World脚本时，我遇到了几个典型问题：

```bash
[root@192 ~]# vim hello.sh
[root@192 ~]# bash hello.sh
Hello world
[root@192 ~]# ./hello.sh
-bash: ./hello.sh: 权限不够
[root@192 ~]# chmod +x hello.sh
[root@192 ~]# ./hello.sh
-bash: ./hello.sh：/bin/bash(B：解释器错误: 没有那个文件或目录
```

第一次用bash hello.sh成功执行后，尝试用./hello.sh执行却报权限不够，加上执行权限后仍然报错。经过排查发现是shebang行存在多余空格导致解释器路径识别失败。修复后成功执行。

**【我的脚本代码】** 

hello.sh：

```bash
#!/bin/bash
echo "Hello world"
```

**【易错点】** 

1. shebang行首不能有多余空格，否则系统无法识别解释器路径，报错/bin/bash(B：解释器错误
2. 在Windows下编辑的脚本可能含有\r\n换行符，导致shebang行实际为#!/bin/bash\r，系统找不到bash\r这个解释器，需用dos2unix命令转换
3. chmod +x后缺少操作数，误写chmod +x而非chmod +x 脚本名
4. 变量赋值时等号两侧不能有空格，如name = yr会报错

### （二）变量与命令替换

**【详细用法】** 

Shell变量赋值使用等号（=），无需声明类型，如a=10。变量引用使用符号，如var或var。命令替换使用(command)语法，可将命令执行结果赋值给变量，如now=(date)。引用变量时建议使用花括号{var}，如${now}，以避免变量名与后续字符粘连产生歧义。

**【原理】** 

Shell变量是简单的键值对存储，所有变量值均为字符串类型。当Shell解析器遇到符号时，会进行变量展开（variableexpansion），将变量名对应的值替换到当前位置。命令替换(command)则是先执行括号内的命令，捕获其标准输出（stdout），再将输出结果作为字符串替换到原位置。花括号${}的作用是界定变量名的边界，防止解析器将后续字符误认为变量名的一部分。

**【我的操作记录】** 

在练习命令替换时，我遇到了以下操作和错误：

```bash
[root@192 ~]# now=$(data)
-bash: data：未找到命令
[root@192 ~]# now=$(date)
[root@192 ~]# echo"$now"
-bash: echo2026年 08月 13日 星期四 16:09:47 CST：未找到命令
```

第一次将data当作命令执行报错，修正为date后成功。但接着在echo和"$now"之间忘记加空格，导致Shell将echo"2026年..."整体当作一个命令来执行，报”未找到命令”。修正后：

```bash
[root@192 ~]# echo "$now"
2026年 08月 13日 星期四 16:09:47 CST
```

**【易错点】** 

1. 变量赋值时等号两侧不能有空格，a=10正确而a = 10会报错
2. echo"now"（前无空格）会报错未找到命令，因为Shell将echo"2026年..."整体当作命令执行，正确写法是echo "$now"（echo和引号间有空格）
3. (data)会报错未找到命令，因为data不是有效命令，正确应为(date)
4. 未引用变量时，含空格的值会被Word Splitting拆分为多个参数，应始终用双引号包裹变量

### （三）位置参数与特殊变量

**【详细用法】** 

Shell脚本支持位置参数传递：0表示脚本名称，1/2/3表示第1/2/3个参数，#表示参数总数，@表示所有参数（以独立字符串形式返回）。特殊变量表示当前进程ID，`?`表示上一个命令的退出码（0表示成功，非0表示失败）。**【原理】**当Shell执行脚本时，会将命令行上的每个单词按空格分割，依次赋值给位置参数`1`、`2`、`3`...。`0`始终为脚本的调用路径。`#`是Shell内置的特殊变量，自动统计位置参数的个数。`@`与`*`的区别在于：`@`保留每个参数的原始分隔（`"param1""param2"`），而`*`将所有参数合并为一个字符串（`"param1param2"`）。由内核在进程创建时设置，表示当前Shell进程的PID。$?由上一条命令的exit状态设置，每次命令执行后自动更新。

**【我的操作记录】** 

我编写了args.sh脚本来测试位置参数的使用：

```bash
[root@192 ~]# ./args.sh
脚本名称：./args.sh
第一个参数：
第二个参数：
第三个参数：
参数总数：0
所有参数（单个）：
[root@192 ~]# ./args.sh 苹果 香蕉 荔枝
脚本名称：./args.sh
第一个参数：苹果
第二个参数：香蕉
第三个参数：荔枝
参数总数：3
所有参数（单个）：苹果 香蕉 荔枝
[root@192 ~]# ./args.sh 备份 数据库 app 每天 凌晨三等
脚本名称：./args.sh
第一个参数：备份
第二个参数：数据库
第三个参数：app
参数总数：5
所有参数（单个）：备份 数据库 app 每天 凌晨三等
```

测试了不传参数和传多个参数的情况，发现1~3只取前三个参数，而#和@能正确处理任意数量的参数。

同时测试了特殊变量：

```bash
[root@192 ~]# echo "当前进程ID：$$"
当前进程ID：2006
[root@192 ~]# echo "上一个退出码：$?"
上一个退出码：0
```

**【我的脚本代码】** 

args.sh：

```bash
#!/bin/bash
echo "脚本名称：$0"
echo "第一个参数：$1"
echo "第二个参数：$2"
echo "第三个参数：$3"
echo "参数总数：$#"
echo "所有参数（单个）：$@"
```

**【易错点】** 

1. 调用脚本时未传参数，1/2等为空白而非报错，需通过$#判断参数数量
2. @与*混用导致参数处理异常，在for循环中遍历参数时应使用"@"而非"*"
3. ?的值在赋值后立即改变，如需保存应第一时间赋值给变量，如ret=?
4. 参数中包含空格时未加引号，导致参数被进一步拆分

### （四）欢迎脚本与登录配置

**【详细用法】** 

综合所学知识，可编写welcome.sh欢迎脚本，利用whoami获取登录用户、date获取当前时间、who | wc -l统计登录人数。将脚本通过sudo cp ~/welcome.sh /etc/profile.d/部署到系统登录配置目录，实现每次用户登录时自动显示欢迎信息。

**【原理】** 

/etc/profile.d/目录下的所有.sh脚本会在用户登录时由/etc/profile自动加载执行。这是Linux系统提供的用户级初始化脚本机制，允许管理员在用户登录时自动运行自定义命令。将欢迎脚本放入此目录，系统会在读取profile配置后依次执行该目录下所有shell脚本。

**【我的操作记录】** 

我编写了welcome.sh脚本并进行了部署：

```bash
[root@192 ~]# ./welcome.sh
===================================
欢迎root登录服务器
当前时间：2026年 08月 13日 星期四 16:38:26 CST
当前用户登录数：2
===================================
[root@192 ~]# sudo cp ~/welcome.sh /etc/profile.d
```

部署后重新登录，成功看到欢迎信息自动显示：

```bash
Last login: Thu Aug 13 15:59:48 2026 from 192.166.166.1
===================================
欢迎root登录服务器
当前时间：2026年 08月 13日 星期四 16:42:37 CST
当前用户登录数：2
===================================
```

**【我的脚本代码】** 

welcome.sh：

```bash
#!/bin/bash
echo "==================================="
echo "欢迎$(whoami)登录服务器"
echo "当前时间：$(date)"
echo "当前用户登录数：$(who | wc -l)"
echo "==================================="
```

**【易错点】** 

1. cp命令后缺少目标路径，误写sudo cp ~/welcome.sh而非sudo cp ~/welcome.sh /etc/profile.d/
2. 脚本中使用了命令替换(whoami)、(date)等，若命令不存在会输出错误信息
3. 部署后需重新登录才能生效，因为profile仅在登录时读取一次
4. 脚本文件编码问题可能导致中文乱码，应确保文件使用UTF-8编码保存
