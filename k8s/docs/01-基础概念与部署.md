# K8s（Kubernetes）学习总结

## 一、K8s基础概念与部署

### （一）K8s架构与核心组件

**【详细用法】** K8s采用Master-Node架构。Master节点运行API Server（kube-apiserver）、Scheduler（kube-scheduler）、Controller Manager（kube-controller-manager）和etcd（数据存储）。Node节点运行Kubelet（节点代理）、Kube-Proxy（网络代理）和容器运行时（containerd/docker）。

常用命令：

```bash
kubectl get nodes — 查看节点状态
kubectl cluster-info — 查看集群信息
kubectl get namespaces — 查看所有命名空间
kubectl create namespace ssim — 创建实验命名空间
```

**【原理】** K8s的核心设计理念是"声明式API"——用户通过YAML/JSON描述期望状态，API Server将期望状态存储到etcd中，Controller Manager通过Watch机制不断对比当前状态与期望状态，驱动系统向期望状态收敛。Scheduler负责将新Pod调度到合适的Node上，Kubelet负责确保Node上的Pod处于运行状态，Kube-Proxy则通过iptables/IPVS实现Service的负载均衡。

**【操作记录】** 在k8s-master01节点上执行kubectl get nodes，确认集群包含master01和多个worker节点；执行kubectl get pods -n ssim查看ssim命名空间下的Pod状态；执行kubectl create namespace ssim创建实验命名空间。

**【易错点】** 1）kubectl命令中namespace参数-n必须与资源实际所在namespace一致，否则会报"not found"错误；2）etcd数据默认存储在/master-data/etcd，误删会导致集群不可用；3）节点标签（label）必须与Deployment的selector精确匹配，否则Pod无法被调度。

### （二）Deployment部署管理

**【完整YAML配置 — deployment.yaml】**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: yuanrui-nginx
  namespace: ssim
  labels:
    creator: yuanrui

# 副本管理
spec:
  replicas: 1
  selector:        # 初始副本数 (会被 HPA 覆盖)
    matchLabels:   # Pod选择器
      app: nginx
      developer: yuanrui
      type: proxy

# 更新策略：始终保证至少有1个可用Pod
strategy:
  type: RollingUpdate    # 滚动更新策略
  rollingUpdate:
    maxSurge: 1          # 更新期间最多新增1个Pod
    maxUnavailable: 0    # 更新期间不允许有不可用Pod

# Pod 标签
template:
  metadata:
    labels:
      app: nginx
      developer: yuanrui
      type: proxy

  spec:
    volumes:
    # 1. 共享临时卷 - 配置中转站
    - name: nginx-config-shared
      emptyDir: {}
    # 2. ConfigMap卷 - 配置仓库
    - name: nginx-config-cm
      configMap:
        name: yuanrui-nginx-config
    # 3. Secret卷 - 安全证书
    - name: tls-secret
      secret:
        secretName: yuanrui-nginx-tls
    # 4. PVC卷 - 持久存储
    - name: mypvc
      persistentVolumeClaim:
        claimName: yuanrui-pvc

    # 初始化容器
    initContainers:
    - name: init-container
      image: registry.cn-hangzhou.aliyuncs.com/duanpc/busybox:1.28.3
      imagePullPolicy: IfNotPresent
      command:
      - sh
      - -c
      - |
        # 将ConfigMap中的配置文件复制到共享卷
        cp /config/default.conf /shared/default.conf
        echo "配置文件已复制到共享卷"
      volumeMounts:
      - name: nginx-config-cm
        mountPath: /config
        readOnly: true
      - name: nginx-config-shared
        mountPath: /shared

    # 主容器
    containers:
    - name: nginx
      image: registry.cn-hangzhou.aliyuncs.com/duanpc/nginx:latest
      imagePullPolicy: IfNotPresent

      # 安全性配置
      securityContext:
        runAsUser: 0

      # 卷挂载
      volumeMounts:
      - name: nginx-config-shared
        mountPath: /etc/nginx/conf.d
        readOnly: true
      - name: tls-secret
        mountPath: /etc/nginx/ssl
        readOnly: true
      - name: mypvc
        mountPath: /data

      # 端口
      ports:
      - containerPort: 80
      - containerPort: 443

      # 环境变量
      env:
      - name: USER
        value: "yuanrui"
      - name: GENDER
        value: "male"
      - name: PLAYER_INITIAL_LIVES
        valueFrom:
          configMapKeyRef:
            name: yuanrui-nginx-config
            key: player_initial_lives
      - name: UI_PROPERTIES_FILE_NAME
        valueFrom:
          configMapKeyRef:
            name: yuanrui-nginx-config
            key: ui_properties_file_name

      # 生命周期管理
      lifecycle:
        postStart:
          exec:
            command:
            - sh
            - -c
            - 'mkdir -p /yuanrui/ && nginx -t'

      # 资源限制
      resources:
        limits:
          cpu: "10m"
          memory: "153Mi"
        requests:
          cpu: "5m"
          memory: "100Mi"

      # 健康检查机制
      readinessProbe:
        httpGet:
          path: /healthz
          port: 80
          scheme: HTTP
        initialDelaySeconds: 10
        timeoutSeconds: 2
        periodSeconds: 5
        successThreshold: 1

      livenessProbe:
        httpGet:
          path: /healthz
          port: 80
          scheme: HTTP
        initialDelaySeconds: 30
        timeoutSeconds: 2
        periodSeconds: 10
        failureThreshold: 3
```

**【详细用法】** Deployment是K8s中管理无状态应用的核心资源，通过管理ReplicaSet来管理Pod。YAML中需指定apiVersion: apps/v1, kind: Deployment, metadata（名称、命名空间、标签）、spec（replicas副本数、selector选择器、template Pod模板、strategy滚动更新策略）。

核心配置说明：

- replicas: 1 — 初始副本数为1（会被HPA覆盖）
- selector.matchLabels — Pod选择器，必须与template.metadata.labels完全一致
- strategy.rollingUpdate — 滚动更新策略，maxSurge: 1表示更新期间最多新增1个Pod，maxUnavailable: 0表示不允许有不可用Pod
- initContainers — 初始化容器，在主容器启动前执行配置初始化
- securityContext.runAsUser: 0 — 以root用户运行容器
- resources.limits/requests — 资源上限和资源请求，用于HPA计算和调度
- readinessProbe/livenessProbe — 就绪探针和存活探针，用于健康检查

**【原理】** Deployment通过创建ReplicaSet来管理Pod。当replicas设为3时，ReplicaSet会确保集群中始终有3个Pod副本运行。滚动更新策略（RollingUpdate）会逐步替换旧Pod：先创建新Pod，等其Ready后再删除旧Pod，确保服务不中断。Deployment记录了所有历史版本，支持回滚到任意历史版本。

初始化容器（Init Container）的工作流程：K8s在Pod调度到Node后，Kubelet首先按顺序执行所有Init Container。每个Init Container必须成功退出（exit code 0）才会执行下一个。所有Init Container执行完毕后，Kubelet才开始启动主容器。本实验使用busybox镜像作为Init Container，将ConfigMap中的Nginx配置文件复制到emptyDir共享卷，主容器从共享卷读取配置文件。

**【操作记录】** 创建yuanrui-nginx Deployment：kubectl apply -f deployment.yaml -n ssim；查看Deployment状态：kubectl get deployment yuanrui-nginx -n ssim，输出显示READY: 1/1, UP-TO-DATE: 1, AVAILABLE: 1, AGE: 91m；查看Pod：kubectl get pods -n ssim。

**【易错点】** 1）selector的matchLabels必须与template.metadata.labels完全一致，否则ReplicaSet无法找到管理的Pod，报"selector does not match template labels"错误；2）滚动更新时若新Pod启动失败（如镜像不存在），旧Pod不会被删除，需手动回滚；3）replicas设为0会删除所有Pod，常用于临时下线服务；4）securityContext.runAsUser: 0表示以root运行容器，安全风险较高，生产环境应使用非root用户并仅添加必要的Capabilities；5）initContainers中的command如果失败（非0退出码），Pod会不断重启该Init Container，需检查命令语法。
